# 安装与自定义

这份文档给第一次用的人：先把这套配置装进 Claude Code，再把它改成你自己的模型、供应商、角色和权限。

日常怎么用、什么话会派给谁，看 [使用指南](使用指南.md)。这里只管装和改。

## 1. 先准备这些

必须有的是 Claude Code。

强烈建议装 magpie。它是一个跑在本机的模型网关，负责把 `group/explore` 这种组名路由到不同供应商的模型。agent 文件里写的模型名要靠它才能解析。安装方法看它自己的 README：Windows 和 macOS 从 https://usemagpie.ai 下载安装包；Linux 可以跑 `curl -fsSL https://usemagpie.ai/install.sh | sh`。

可选三样：Orca，用来并行起 worker 会话跑实现类任务，也可以把 worker 派进 WSL；mattpocock/skills，一套拷问、出规格、拆票、实现、审查的流程技能；WSL，想在 Linux 环境里干活时用。前两样不装，这套配置也能用，只是少了并行实现和那套流程。

## 2. 装进去

下面的命令在仓库根目录执行。脚本会先备份同名的旧文件，再把仓库里的文件拷过去。两段命令做的是同一件事，按你的系统选一段。

PowerShell：

```powershell
$dst = "$HOME/.claude"; $ts = Get-Date -Format yyyyMMdd-HHmmss
if (Test-Path "$dst/agents") { Copy-Item -Recurse "$dst/agents" "$dst/agents.bak-$ts" }
if (Test-Path "$dst/CLAUDE.md") { Copy-Item "$dst/CLAUDE.md" "$dst/CLAUDE.md.bak-$ts" }
New-Item -ItemType Directory -Force "$dst/agents", "$dst/skills" | Out-Null
Copy-Item claude-code/agents/*.md "$dst/agents/"
Copy-Item -Recurse -Force claude-code/skills/dispatch "$dst/skills/"
```

bash（macOS / Linux / Git Bash）：

```bash
DST="$HOME/.claude"; TS=$(date +%Y%m%d-%H%M%S)
[ -d "$DST/agents" ] && cp -r "$DST/agents" "$DST/agents.bak-$TS"
[ -f "$DST/CLAUDE.md" ] && cp "$DST/CLAUDE.md" "$DST/CLAUDE.md.bak-$TS"
mkdir -p "$DST/agents" "$DST/skills"
cp claude-code/agents/*.md "$DST/agents/"
cp -r claude-code/skills/dispatch "$DST/skills/"
```

同名 agent 会被覆盖，所以脚本第一步先备份。想装到别的位置，改开头那个目标变量就行，PowerShell 里是 `$dst`，bash 里是 `$DST`。

拷完之后，把 `claude-code/CLAUDE.md片段.md` 里的代码块贴进 `~/.claude/CLAUDE.md`。贴完新开一个会话才生效，当前会话不会热加载 CLAUDE.md。

只想在某个项目里用，就把 agent 文件拷到该项目的 `.claude/agents/`，把 dispatch 拷到 `.claude/skills/`。项目级和全局有同名 agent 时，项目级优先。

## 3. 换成自己的模型

agent 文件和手册之间靠九个角色组约定（随附配置里是这九个）：`explore`、`research`、`extract`、`review`、`diagnose`、`write`、`verify`、`impl`、`impl-strong`。组里放什么模型由组合文件决定，不一定是 GLM，名字只是为了让 agent 文件有个稳定的引用。

示例里另外还有四个档位组：`glm-main`、`glm-fast`、`minimax`、`ds-flash`。它们对应 Claude Code 的 opus、sonnet、haiku、fable 别名，给没有写死角色组的地方用。

照 [magpie/路由组与档位.md](../magpie/路由组与档位.md) 建四个档位组，把命令里的 `<来源>/模型` 换成你自己的。哪些来源和模型可用，用 `magpie providers` 和 `magpie models claude` 查。

角色组不用手建，由 `claude-code/skills/dispatch/组合/` 下的 `国产.txt` 和 `Codex.txt` 生成。先用 `magpie providers` 查到供应商 id，把文件里的 `<国产来源>`、`<Codex来源>`、`<Claude来源>` 替换掉，再跑切换脚本：

```text
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" 国产
```

一个组可以放多个成员。`routing=order` 时按顺序试，前一个不可用就用下一个，适合拿便宜的同档模型兜底。示例的 Codex 组合里，每个角色组都是 Codex 成员排第一、国产模型排第二，顺序可以按需要调整。

想改组名也可以，但 agent 文件、派活手册（`claude-code/skills/dispatch/SKILL.md`）、组合文件和 CLAUDE.md 片段里都引用了组名，要一起改。用编辑器的全局查找替换最快。

## 4. 推理档位和上下文长度

agent 文件里现在只写角色组，比如 `model: group/explore`，不带档位。档位由组合文件里的成员决定，agent 文件不再管这件事。

组合文件里的成员写法是 `供应商/模型[:推理档位][:fast]`。示例把档位收在 `medium`、`high`、`xhigh` 三档，可按模型支持和任务需要调整。一个成员可以写多档，表示这几档都接，具体用哪档由派活时的 `--effort` 决定，比如 `:medium+high+xhigh`；组上再配 `levels=medium,high,xhigh` 把范围收住。示例里 GLM 和 DeepSeek 只有 low/high/max，所以钉 `:high`；MiniMax 和 Codex 写成 `:medium+high+xhigh`。

成员必须把支持的档位写全，尤其是 Codex 这类多档模型。不写档位时，收到网关不支持的档位请求可能被跳过，整轮落到兜底成员上。这个坑在一台测试机上实测过。

如果你不用组合文件，直接手写成员，也可以把档位写进 agent 文件，比如 `model: group/explore:medium`。`:medium` 是 magpie 的推理档位写法，在一台测试机上能被 Claude Code 识别。

Claude Code 官方还有自己的 frontmatter 字段 `effort`，取值是 `low`、`medium`、`high`、`xhigh`、`max`。不用 magpie 的时候用它来定推理档位；用 magpie 的组时，以组里的成员档位为准。

## 5. 不用 magpie 怎么改

把每个 agent 文件里的 `model:` 改成 Claude Code 官方支持的写法：别名 `sonnet`、`opus`、`haiku`、`fable`，完整模型 id（比如 `claude-haiku-5-5`），或者 `inherit`（跟随主会话）。推理档位改用上一节说的 `effort:` 字段。

要注意，Claude Code 直连时只能用 Anthropic 的模型。想用 GLM、MiniMax、DeepSeek、Codex 这类模型，中间需要一个能把它们转成 Anthropic 接口的网关，magpie 是其中一种。

## 6. 改角色

每个 agent 文件头部有一段 frontmatter，`description` 决定主会话会不会主动派它。写的时候别写"我是某某专家"，写"什么时候该派我"，并在里面加一句"主动使用（use proactively）"。不想让它被自动派，就明确写"不主动使用"，verifier 就是这么写的：只在点名、关键决策复核、上线前验收、两个执行者结论冲突时才派。

frontmatter 下面的正文是它的工作规则。格式照现有文件抄一份就能加新角色：文件名叫什么，agent 就叫什么。用不上的 agent 可以删，只要 CLAUDE.md 片段和派活手册里不再引用它。新增角色时记得在组合文件里也加一个同名的角色组，否则 agent 文件里的 `group/<新角色>` 找不到。

## 7. 改权限

只读 agent 靠 frontmatter 的 `disallowedTools` 屏蔽写操作。仓库里的文件列了一些 `mcp__kb-backend__…`、`mcp__ssh-mcp-server__…`、`mcp__magpie-image__…` 的工具名，那是作者自己装的 MCP 服务。你装的服务不一样，换成你自己 MCP 的写操作工具名。

写法有三种：单个工具写 `mcp__服务名__工具名`；屏蔽整个服务写 `mcp__服务名__*`；屏蔽所有 MCP 工具写 `mcp__*`。

列了不存在的工具名一般不影响使用，不过这一点没实测过，装完用 `/agents` 看一眼，确认 agent 都在、没报错。

另外，`Bash` 仍然开着。"只读"对 Bash 只是写在 agent 正文里的规则约束，不是工具层面的硬限制，真正防误写还得靠规则和验收。

## 8. 验证装好了没有

新开一个会话，说一句"派 explorer 看看这个项目做到哪了"。它应该去读项目结构和 git 历史，回来给你带文件路径和行号的结论。

用 magpie 的话，跑 `magpie usage --csv --last 1h`，看 `requested_model`、`served_model`、`effort` 三列。requested 是你写的角色组，served 是实际落到的模型，effort 是档位，三个都对上说明配置生效了。

想确认 agent 都装上了，用 `/agents` 命令看列表。

## 9. WSL 里也用同一份

Windows 上装好之后，WSL 里可以共用这份配置。把 `claude-code/skills/dispatch/WSL/同步配置到WSL.py` 放到 `~/.claude/skills/dispatch/WSL/`（随整个 dispatch 目录一起拷过去就有），在 WSL 里运行：

```text
python3 /mnt/c/Users/<用户名>/.claude/skills/dispatch/WSL/同步配置到WSL.py
```

它会做三件事：能共享的配置建符号链接指向 Windows 那份；`settings.json` 和 Codex 的 `config.toml` 从 Windows 版生成一份 WSL 版；MCP 里能在 Linux 下跑的合并过去，Windows 专用的跳过并列出名字。不传参数时自动推断 Windows 家目录，推断不出来就把路径作为第一个参数传进去。

Windows 那边改了 `settings.json`、Codex 配置或 MCP 之后，要重跑一次这个脚本。更完整的两种用法（从 Windows 派 worker 进 WSL，或者直接在 WSL 里开主会话）看 [使用指南](使用指南.md) 的 WSL 一节。

## 10. 装坏了怎么退回去

agent 和 CLAUDE.md 的备份在 `~/.claude/agents.bak-时间戳` 和 `~/.claude/CLAUDE.md.bak-时间戳`，把对应目录和文件拷回原位就行。

magpie 的组配置在改之前用 `magpie save <名字>` 存过快照的话，跑 `magpie use <名字>` 就能恢复。没存过快照就只能手动改回去。切换组合本身会重建九个角色组，切回另一个组合就能覆盖回来。
