# 安装与自定义

这份文档给第一次用的人：先把框架装进 Claude Code 或 Codex（两个都装也行），再跟着初始化引导生成你自己的个人配置，最后按需要改模型、角色和权限。

日常怎么用、什么话会派给谁，看 [使用指南](使用指南.md)。这里只管装和改。

## 1. 先准备这些

框架分三层，有哪层用哪层，不用一次装齐：

- 基础层：Claude Code（或 Codex）。只有它也能用：主会话按手册把活派给 7 个具名子代理。
- 底座层：加 [Orca](https://github.com/stablyai/orca) 和 [magpie](https://github.com/yetone/magpie)。Orca 用来并行起 worker 会话跑实现类任务；magpie 是跑在本机的模型网关，把 `group/explore` 这种组名路由到不同供应商的模型，agent 文件里写的组名要靠它解析。magpie 的安装看它自己的 README：Windows 和 macOS 从 https://usemagpie.ai 下载安装包；Linux 可以跑 `curl -fsSL https://usemagpie.ai/install.sh | sh`。
- 进阶层：加 WSL 或一台远程 Linux 执行机，加多模型组合。测试、构建、Docker 放到执行机上跑，Windows 主会话通过 Orca 把 worker 派过去。

另外可选 [mattpocock/skills](https://github.com/mattpocock/skills)：一套拷问、出规格、拆票、实现、审查的流程技能，手册里写了怎么和它配合。

## 2. 装进去

在仓库根目录运行安装脚本。先演练看它要做什么，再正式装：

```text
python 安装.py --演练
python 安装.py
```

Linux、macOS、WSL 里用 `python3`。

脚本按本机装了什么自动选宿主：`claude` 命令在 PATH 里或 `~/.claude` 目录存在，算有 Claude Code；`codex` 命令在 PATH 里或 Codex 家目录存在，算有 Codex。只有一个就装给它；两个都有时默认只装 Claude Code（以前用过 Claude Code、留着 `~/.claude` 目录的 Codex 用户要注意，用 `--宿主 codex` 指定）；一个都没检测到就报错退出，让你用 `--宿主` 指定。两边都装加 `--宿主 both`，也可以用 `--宿主 claude-code` 或 `--宿主 codex` 指定。旧参数 `--codex` 等同 `--宿主 both`。

它只动框架文件：

- Claude Code：`~/.claude/skills/` 下的 `dispatch`、`dispatch-retro`、`dispatch-feedback` 三个目录，和 `~/.claude/agents/` 下的 7 个 agent。
- Codex：`~/.agents/skills/` 下同样三个技能，和 `<Codex家>/agents/` 下的 7 个角色文件（`<Codex家>` 是 `CODEX_HOME`，没设就是 `~/.codex`）。角色文件从同一份 agent 正文生成，只写名字、说明和角色说明，不写模型和档位。另外，环境变量 `DISPATCH_CONFIG_DIR` 没设、`~/.dispatch/config.toml` 和旧的 `~/.claude/派活配置/` 都不存在时，写一份默认的 `~/.dispatch/config.toml`；有任何一样就不写。

被替换的旧文件先备份到 `~/.dispatch/备份/<时间>-安装前/`。你改过的 agent 或角色文件默认保留不覆盖，要覆盖加 `--覆盖agent`（旧的同样先备份）。已有的个人配置、`~/.claude/CLAUDE.md`、Codex 的 `config.toml` 和 `AGENTS.md` 都不碰。

升级也是重跑这一条：框架文件换成新版，个人配置原样保留。

## 3. 初始化引导

装完新开一个会话，Claude Code 里输入 `/dispatch-retro`，Codex 里输入 `$dispatch-retro`（Codex 里它只能这样显式调用，技能列表里看不到是正常的）。引导会做这几件事：

1. 用三五句话说清框架怎么分工、分哪几层，问你现在开始还是稍后。
2. 自己探测能查到的：CPU、内存、磁盘，装了哪些 agent 工具，有没有 Orca、magpie、WSL、远程执行机，magpie 里有哪些模型来源。
3. 告诉你现在能用到哪一层、缺的那层装了能多什么，装不装你定。
4. 把探测不出来的事一次问完，每个问题给推荐：用哪些模型来源、订阅还是按量、每分钟请求上限、预算、额度到预警线怎么办、质量和成本怎么取舍、哪些模型不用。
5. 生成个人配置 `~/.dispatch/`：`本机条件.md`、体检用的 `检查配置.json`；用 magpie 的再加在用组合（从示例复制一份，把来源换成你的）；用 Codex 的核对 `config.toml` 里的模型名是不是你的 Codex 里都有；有远程执行机时再加项目登记。
6. 问你要不要把规则片段加进全局规则：Claude Code 用 [CLAUDE.md片段.md](../CLAUDE.md片段.md)，加进 `~/.claude/CLAUDE.md`；Codex 用 [AGENTS.md片段.md](../AGENTS.md片段.md)，加进 `<Codex家>/AGENTS.md`。
7. 应用组合（会改 magpie，先征得你同意），跑一次体检，派一个 explorer 小活核对它落在哪个模型。
8. 在 `复盘记录.md` 记第一条，告诉你日常怎么用。

改 magpie、`settings.json`、`CLAUDE.md`、agent 文件之前，引导都会先说清楚改什么、为什么，等你点头，改前备份。

以后机器、额度或习惯变了，再输入 `/dispatch-retro` 复盘：它读上次以来的反馈和用量，给出调整建议，由你决定；框架本身的问题会起草成 issue 给你看。

## 4. 个人配置里有什么

```text
~/.dispatch/
├── config.toml      各角色走原生子代理还是 Orca、哪个宿主、什么模型和档位（可选）
├── 本机条件.md      层级、并发、额度、预算、机器、远程执行机、模型禁忌
├── 组合/            在用组合（如 Codex.txt）和 当前组合.txt
├── 检查配置.json    体检和落点检查的阈值、远程环境、扩展检查
├── 项目.json        有远程执行机时，Windows 和 WSL 两份检出的对应关系
├── 反馈/            项目会话用 dispatch-feedback 写进来的反馈
├── 复盘记录.md      每次复盘改了什么、待观察什么
├── 备份/            安装器和引导、复盘改动前的备份
└── 状态/            脚本自己记的状态，不用管
```

环境变量 `DISPATCH_CONFIG_DIR` 可以把它换到别的位置。这个目录不在仓库里，升级框架、同步仓库都不会碰它。v3.1 及以前的个人配置在 `~/.claude/派活配置/`，没有 `~/.dispatch/config.toml` 时脚本照样读旧位置，不用搬；要搬就把整个目录挪到 `~/.dispatch/`，在里面放一份 `config.toml`（只写 `version = 1` 也行）。

`config.toml` 的写法：

```toml
version = 1
executor = "<执行机名>"   # 可选，默认执行机

[roles.reviewer]
mode = "native"           # native 原生子代理，或 orca
host = "codex"            # codex 或 claude-code
model = "<模型名>"
effort = "xhigh"          # medium、high、xhigh
```

`version = 1` 必须写，其余都可以不写。角色下四项不写时：`mode` 普通角色是原生子代理（`implementer` 只能是 orca）；`host` 是主会话所在的宿主；`model` 用宿主默认（Claude Code 是 agent 文件里的，Codex 是主会话的）；`effort` 由主会话每次决定。宿主是 claude-code 的原生角色，模型只能写 opus、sonnet、haiku、fable 四个别名，要别的模型就走 Orca。

项目根目录放一份同样格式的 `.dispatch.toml`，会覆盖个人配置里的同名项，适合提交进仓库让整个项目统一。脚本从当前目录往上找最近的一份，找到含 `.git` 的那层为止。

改完跑 `python <本技能目录>/脚本/生效配置.py` 看合并后的结果。校验分两步：先单独查每个文件的结构（不认识的键或角色、值的类型不对，都会报出文件和项，这个文件整份不参与合并）；再查合并后的语义（比如 implementer 写成 native、claude-code 原生角色写了别名以外的模型）。有错时脚本退出码是 2。

## 5. 换成自己的模型

Codex 当主会话、不用 magpie 的，改 `config.toml` 里各角色的 `model` 和 `effort` 就行，下一次派活生效，角色文件不用动；这一节下面和第 6、7 节说的是 Claude Code 加 magpie 的。

agent 文件和手册之间靠十个角色组约定：`explore`、`research`、`extract`、`review`、`diagnose`、`write`、`verify`、`impl-lite`、`impl`、`impl-strong`。组里放什么模型由组合文件决定，名字只是为了让 agent 文件有个稳定的引用。三个实现组只是分组定义：清单式的确定性活、常规实现、复杂实现，放不放更强的模型由你按额度定，第一顺位相同时 impl-strong 就等于 impl 加高推理档。

示例组合在 `skills/dispatch/组合/` 下：`国产.txt`（GLM / MiniMax / DeepSeek）和 `Codex.txt`（Codex 三个模型）。初始化引导会复制一份到个人配置的 `组合/` 下，把 `<国产来源>`、`<Codex来源>`、`<Claude来源>` 换成你在 `magpie providers` 里看到的来源 id。之后改个人配置里那份，再跑切换脚本：

```text
python ~/.claude/skills/dispatch/组合/切换组合.py Codex
```

一个组可以放多个成员。`routing=order` 时按顺序试，前一个不可用就用下一个，适合拿便宜的同档模型兜底。组合文件末尾的 `magpie claude` 行决定 Claude Code 的 fable、opus、sonnet、haiku、subagent 档位指向哪个组，示例按大小排：fable 给复杂票，sonnet 给确定性的清单活，haiku 给 Claude Code 自己的后台小活（别指向订阅类来源，会挤占每分钟请求名额）。建组、档位组、快照的细节看 [magpie/路由组与档位.md](../magpie/路由组与档位.md)。

想改组名也可以，但 agent 文件、手册、组合文件里都引用了组名，要一起改。

## 6. 推理档位

agent 文件里只写角色组，比如 `model: group/explore`，不带档位。原生子代理的档位由组合文件里的成员钉死，比如 `<来源>/模型:medium:fast`；成员钉了档位，调用方要什么都按钉的发。Orca worker 的档位由主脑每次用 `--effort` 选，实现组成员写成 `:medium+high+xhigh` 表示这三档都接。

成员必须把支持的档位写全。不写档位时，收到网关不支持的档位请求可能被跳过，整轮落到兜底成员上，这个坑在一台测试机上实测过。

## 7. 不用 magpie 怎么改

初始化引导会发现你没有 magpie，列出要改哪些 agent。手动改的话：把每个 agent 文件里的 `model:` 改成 Claude Code 官方支持的写法，别名 `sonnet`、`opus`、`haiku`、`fable`，完整模型 id，或者 `inherit`（跟随主会话）；推理档位用官方的 `effort:` 字段。

Claude Code 直连时只能用 Anthropic 的模型。想用 GLM、MiniMax、DeepSeek、Codex 这类模型，中间需要一个能把它们转成 Anthropic 接口的网关，magpie 是其中一种。

## 8. 改角色

每个 agent 文件头部的 `description` 决定主会话会不会主动派它。写“什么时候该派我”，并加一句“主动使用（use proactively）”；不想被自动派就明确写“不主动使用”，verifier 就是这么写的。

frontmatter 下面的正文是它的工作规则。照现有文件抄一份就能加新角色，文件名就是 agent 名。新增角色时记得在组合文件里加一个同名的角色组。

Codex 的角色 toml 是安装器从仓库 `agents/` 下同一份正文生成的。改角色最好改 `agents/` 里的正文再重跑安装器，两边一起变；直接改 `<Codex家>/agents/` 下的 toml 也行，安装器默认保留你改过的文件，只是以后升级不会自动带上新正文。toml 里别写 model，模型写在 `config.toml`。

## 9. 改权限

只读 agent 靠 frontmatter 的 `disallowedTools` 屏蔽写操作。仓库里列了一些 `mcp__kb-backend__…`、`mcp__ssh-mcp-server__…`、`mcp__magpie-image__…`，那是作者自己装的 MCP 服务，换成你自己 MCP 的写操作工具名。写法：单个工具 `mcp__服务名__工具名`；整个服务 `mcp__服务名__*`；所有 MCP 工具 `mcp__*`。

`Bash` 仍然开着。“只读”对 Bash 只是规则约束，不是工具层面的硬限制，真正防误写还得靠规则和验收。

Codex 的角色文件改不了沙箱和审批设置，子代理继承主会话的，所以 Codex 下没有这一层。只读靠角色前言加主会话前后各跑一次 `git status --short` 核对，见手册 `参考/宿主差异.md`。

## 10. 验证装好了没有

新开一个会话，说“派 explorer 看看这个项目做到哪了”，回来的结论应该带文件路径和行号。Codex 当主会话的，再打开 `<Codex家>/sessions/` 下最新的子代理会话文件，看 `model` 和 `reasoning_effort` 是不是 `config.toml` 里写的。用 magpie 的话跑 `magpie usage --csv --last 1h`，看 `requested_model`、`served_model`、`effort` 三列。有 Orca 和 magpie 的，跑一次体检：

```text
python ~/.claude/skills/dispatch/脚本/体检.py      # Codex 下是 ~/.agents/skills/dispatch/脚本/体检.py
```

没装的工具（magpie、Orca、Claude Code）体检会跳过并说明，不算失败。只用 Codex 的，核对子代理实际模型的办法见手册 `参考/宿主差异.md`。

## 11. WSL 和远程执行机也用同一份

先在个人配置目录写一份 `执行机.toml`，登记每台执行机（WSL 写发行版名，远程 Linux 写 `~/.ssh/config` 里的别名，写法见 `skills/dispatch/模板/执行机示例.toml`）。然后在主机上跑：

```text
python ~/.claude/skills/dispatch/脚本/同步执行机.py --列出
python ~/.claude/skills/dispatch/脚本/同步执行机.py <名称>          # 只预览
python ~/.claude/skills/dispatch/脚本/同步执行机.py <名称> --执行   # 先备份再写，写完调一次模型验证
```

只装了 Codex 的把路径换成 `~/.agents/skills/dispatch/`。它按固定清单同步规则、角色、技能和个人配置，从主机版生成执行机上的 `settings.json`、Codex 的 `config.toml` 和 MCP；远程 Linux 上认证文件、私钥、浏览器登录态、缓存、历史会话、hooks 永远不复制。WSL 上共享项是指向 Windows 那份的链接，远程 Linux 上是复制，主机改了要再同步一次。代理类环境项（`HTTP_PROXY`、`NO_PROXY` 这些）在远程 Linux 上跟着目标机，不从主机带；网关地址换成 `执行机.toml` 里登记的 `magpie_url`。执行机上还没装 CLI 的，用 `--装CLI` 预览、加 `--执行` 安装，单项最多等 30 分钟。Codex 用 ChatGPT 登录的，到执行机上自己 `codex login` 一次。备份位置、网关地址和密钥怎么给、两种用法（从主机派 worker 进执行机，或直接在执行机里开主会话）见手册的 `参考/远程执行机.md`。

以前在 WSL 里跑的 `WSL/同步配置到WSL.py` 还能用，一跑就写、不做模型验证。

## 12. 装坏了怎么退回去

安装脚本替换的旧文件在 `~/.dispatch/备份/<时间>-安装前/`（v3.1 及以前在 `~/.claude/备份/`），按里面的相对路径拷回家目录下原位就行；其中 `.codex/agents/` 那部分要拷回 `<Codex家>/agents/`（设了 `CODEX_HOME` 时就不是 `~/.codex`）。初始化引导和复盘改的东西，备份在 `~/.dispatch/备份/<日期>-引导前/` 或 `-复盘前/`。

magpie 的组配置在改之前用 `magpie save <名字>` 存过快照的话，`magpie use <名字>` 就能恢复。切换组合本身会重建所有角色组，切回另一个组合就能覆盖回来。

## 从 v3.1 及以前升级

`git pull` 后重跑 `python 安装.py`。只用 Claude Code 的，什么都不用改：个人配置还在 `~/.claude/派活配置/`，脚本照样读，规则意思没变。

想用新位置的，把整个 `~/.claude/派活配置/` 挪到 `~/.dispatch/`，在里面放一份 `config.toml`（只写 `version = 1` 也行）；还有别的东西写死了旧路径的，可以在旧路径留一个指向新目录的链接（Windows 上用目录联接）。要在 Codex 里当主会话，再跑一次 `python 安装.py --宿主 codex`（或 `both`），然后照第 4 节在 `config.toml` 里给各角色写模型和档位。

以前用 `WSL/同步配置到WSL.py` 的，可以改用主机上的 `脚本/同步执行机.py`，先预览。新脚本不再新建 Codex 登录态的链接，已有的不动。

## 从 v2 升级

v2 把手册、组合和本机条件都放在 `~/.claude/skills/dispatch/` 里，v3 把个人的部分搬到 `~/.claude/派活配置/`：

1. 先备份 `~/.claude/skills/dispatch/`。
2. 把你改过的组合文件（`组合/*.txt`、`当前组合.txt`）拷到 `~/.claude/派活配置/组合/`；有 `本机/` 目录的，把里面的文件拷到 `~/.claude/派活配置/`。
3. 跑 `python 安装.py`。
4. 新开会话输入 `/dispatch-retro`，复盘核对一遍个人配置。

脚本找不到个人配置目录时会回落到 skill 里的旧位置，所以第 2 步之前也不会坏，只是会用 skill 自带的示例组合。
