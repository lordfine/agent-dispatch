# 派活记录

用途：复盘时按任务类型和确定性分组，比较首交通过率、首交到结案的墙钟和总返工轮次。未知和未结案的单独计数，不从分母里去掉。

## 人工部分：写在规格开头

主脑派活时本来就要定档，顺手写进规格开头四行（见 `模板/规格.md`）：风险档、确定性、推理档、返工原因。返工时在新规格里写“返工原因：第 N 次，<原因>”。这是唯一需要人写的部分。

## 自动部分：由脚本拼

- Orca：`task-list`、`dispatch-show` 给出任务标题、派出时间、完成时间、状态，`follow_up_of_dispatch_id` 串起同一张票的返工链（见 `参考/Orca.md`）。
- magpie：`magpie usage --csv` 按会话和时间给出实际落点模型和档位。
- 交付文件：测试结果、通过数、改动统计（交付模板的固定字段）。

拼出来每个事件一行 JSON，写到项目的 `.claude/派活记录.jsonl`。事件只用派出、首交、返工、结案、取消；结果在结案或取消时填通过、撤回、拆票、取消，其余事件记 `null`。未知值记 `null`；不记录任务正文、凭据或连接串。

```jsonl
{"时间":"2026-01-01T10:00:00+08:00","事件":"派出","任务ID":"任务-示例","尝试":1,"任务类型":"修复","风险档":"中","确定性":"确定","请求":{"组":"impl","档位":"high"},"落点":null,"返工原因":null,"测试结果":{"通过":null,"失败":null,"跳过":null},"结果":null}
```

拼记录的脚本还没写，先按规格开头四行试点一个批次；脚本写好后由 `dispatch-retro` 复盘时调用。
