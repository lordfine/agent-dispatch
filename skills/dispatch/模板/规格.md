## 实现者固定规则（原样带上）
- 先读规格和 AGENTS.md，不回退别人的改动。
- Bash 每次只跑一条直接命令，不加 `cd`、不用 `&&` 和管道。
- bash 脚本的变量名、函数名只用英文（bash 不认中文标识符，`日志=...` 会被当成命令）；中文只放在字符串和路径里。
- 往 WSL 传带 `$变量` 或 `$(...)` 的命令，一律先写成脚本文件再 `wsl -d <发行版> -- bash <脚本>` 执行；直接塞进 `wsl -- bash -c "..."`，变量会被 PowerShell 或外层 shell 提前展开或吃掉（实战项目批13 实测：读文件得到空串，PG 用例全部静默跳过）。git 输出中文路径要加 `-c core.quotePath=false`，否则是八进制转义，grep 中文文件名会搜空。
- 新功能和修 bug 先写能失败的测试，再做最小实现，从对外接口观察行为；机械活不要求。只跑定向测试；返工后只重跑失败和受影响的测试，真实捕获退出码。
- 收紧类改动（缺了 X 就拒绝）：用 grep 找出所有直接调用被收紧入口的测试，逐处说明为什么不受影响。
- 规格要求交付前跑全量时，用 `bash ~/.claude/skills/dispatch/脚本/全量排队.sh --no-wait --label "<票名>" -- <全量命令>`；退出码 75 表示名额被占，不等，在交付里写“全量未跑：占用”。
- 停在“改完未提交”：不 commit、不 push、不自行回传最终结论。
