# WSL 和远程执行机

需要：进阶层。个人配置里没有登记 WSL 或远程 Linux 执行机就不用读；没有的话 worker 直接在本机跑，测试和 Docker 用自己已有的环境。本机的具体值（发行版、用户、远程服务器名、地址、envId、repoId、路径）见个人配置 `本机条件.md`。

开发机的 WSL 是 `<发行版>`（用户 `<WSL用户>`，ext4；资源见个人配置）。里面装了 claude、codex、uv、node，配置和 Windows 共用一份：`~/.claude/CLAUDE.md`、`agents`、`skills`、`派活配置`、`~/.codex/AGENTS.md`、`auth.json` 是指向 Windows 的链接，改 Windows 那份两边生效；`settings.json`、Codex 的 `config.toml`、MCP 是从 Windows 版生成的，Windows 那边改了这三样要在 WSL 里重跑一次：
```text
python3 /mnt/c/Users/<用户>/.claude/skills/dispatch/WSL/同步配置到WSL.py
```
magpie 跑在 Windows 上时，WSL 按自己的网络模式连它（mirrored 网络可以直接用回环地址；地址和代理见个人配置）。依赖 Windows 专用路径的 MCP 在 WSL 里带不过去，同步脚本会跳过并列出名字，要用这些就在 Windows 会话里做。

不做：不重启 WSL、不改 `.wslconfig`（有别的项目在 WSL 里部署，要重启先问用户）。重建 Orca 到 WSL 的连接，事先当作重启 WSL 征求用户同意（11-07 实测：断开那条 SSH 会话后发行版被整个重启了一次）。

## 用法一：Windows 主会话派 worker 到 WSL

Orca 通过 SSH 远程服务器 `<远程服务器名>`（地址见个人配置，免密钥口令）连进 WSL，在 Orca 的“远程 Orca 服务器”里能看到它。项目要先在 WSL 里 clone 一份放在 ext4 上（如 `~/work/<项目>`），再登记成 `<远程服务器名>` 上的项目：
```text
orca project setup-existing-folder --host <envId> --path /home/<WSL用户>/work/<项目>
```
登记后拿到 repoId。目前远程主机上起的是终端模式（Orca 1.4.251 回执写明）。三种写法：

- 新票、新工作区（远程不能用 current 和 new-child，用 new-top-level；基线由 `orca repo set-base-ref` 定好，一般不用 `--base-branch`）：
```text
orca orchestration worker-start --on <远程服务器名> --worktree new-top-level --repo id:<repoId> --name <短名> --spec-file <说明.md> --task-title "<标题>" --agent claude --model group/impl --effort <档位> --keep-open
```
- 同一张票返工：远程 worker 已完成时不能用 `send`，在原终端继续同一张票，`--worktree` 写原工作区的精确选择器：
```text
orca orchestration worker-start --on <远程服务器名> --worktree <原工作区精确选择器> --terminal <原终端句柄> --spec-file <说明.md>
```
  复用原终端时不能带 `--agent`、`--model`、`--effort`；原会话上下文还在，只用于同一张票的返工或补充，换下一张票就开新会话。用完执行 `orca orchestration worker-release --dispatch <id>`。
- 只读审查已有工作区：`--worktree "id:<repoId>::<该工作区的路径>"`，指向要审的那个工作区，不是主检出。

不要把 `--worktree` 指向主检出路径，那样 worker 会直接在主检出里改。三种写法由 实战项目下批首次使用时实测确认（Orca 1.4.251 帮助写明：远程不能用 current 和 new-child，新工作区用 new-top-level）。

- 依赖（`.venv`、`node_modules`）在 WSL 里单独装，不链接 Windows 检出里的。
- 看远程终端内容：`orca terminal read --environment <远程服务器名> --terminal <终端句柄>`。WSL worker 交回的交付文件路径在 WSL 里，用 `wsl -d <发行版> -- cat <路径>` 读（PowerShell 里直接用；Git Bash 会把 /home 改写成 Windows 路径，要在前面加 `MSYS_NO_PATHCONV=1`，11-07 实测）。
- 守护进程刚重启后，第一次远程派活可能报 “Timed out waiting for the remote Orca runtime”：先用 `worktree list` 确认没有半成品，再重试（实战项目批13 实测）。
- `agent_prompt_blocked`：按官方 orca-cli 指南处理（菜单出现时分开发 `--text` 和 `--enter`）。如果是 claude 首次运行的提示，回答后把对应的“已看过”键加进同步脚本。
- `hasSeenAutoDefaultNudge`：1.4.250 实测；官方 1.4.251 指南未提，已知提示是“要不要把 auto 设为默认权限模式”，同步脚本已处理。
- WSL 的资源和并发上限见个人配置。
- Windows 和 WSL 两份检出之间取分支、合并、取回 Windows，用 `脚本/WSL衔接.py`（先加 `--演练` 看要跑哪些命令）。

## 用法二：直接在 WSL 里开主会话

在 WSL 终端里 `cd ~/work/<项目>` 后运行 `claude` 或 `codex`。规则、agent、本手册都是同一份，原生子代理照常派。要让会话在 Windows 的 Orca 里看得到、管得到，不要在裸 WSL 终端里起，而是在 Orca 里打开 `<远程服务器名>` 上的这个项目，从 Orca 的终端里起 `claude`；Orca 的 worker 也只能从 Orca 里的会话派。切组合用 `组合与路由.md` 里的 WSL 命令。
