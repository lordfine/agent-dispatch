# 验收与测试

需要：基础层。全量排队脚本需要 Linux 的 `flock`（WSL 或 Linux 执行机都有）。

## 全量测试什么时候跑

- 集成前、发版前各跑一次，必须拿到结果。
- 大档票和改全局语义的票，交付前再跑一次（11-09 作者定），用不等待的方式排队：拿到名额就跑，被占就跳过，交付里写“全量未跑：占用”。理由是晚发现的代价远大于一次全量（实战项目批15：隐私票合入后埋下的 142 项失败 17 小时后才暴露，接着返工 3 轮）。
- 小档、中档 worker 只跑定向测试；返工后只重跑失败和受影响的测试。审查员只跑复现问题所需的最小用例。

## 多个会话之间不冲突

一台测试机同一时间只跑一个全量，用 `脚本/全量排队.sh` 挡，不靠各会话自觉：
```text
bash ~/.claude/skills/dispatch/脚本/全量排队.sh --status
bash ~/.claude/skills/dispatch/脚本/全量排队.sh --no-wait --label "<票名>" -- bash <项目的全量脚本>
bash ~/.claude/skills/dispatch/脚本/全量排队.sh --wait-minutes 180 --label "集成前" -- bash <项目的全量脚本>
```
`--no-wait` 被占时退出码 75，用于大档票交付前；集成前、发版前用等待方式。`--status` 显示谁占着、从几点开始。

拿着名额时，脚本给命令一个每次不同的 `FULL_TEST_RUN_ID`。项目的全量脚本要做到：
- 日志、junit、临时目录用 `FULL_TEST_RUN_ID` 拼目录名，不用固定名，更不要跑前 `rm -rf` 固定目录（实战项目11-09 核查：固定日志目录两会话同跑会互删）。
- 测试库的 schema、库名、角色名用随机名，不用固定名。
- 全量在跑时，不重启测试库容器、不改数据库参数（会掐断正在跑的连接），这类动作先 `--status` 确认空闲，再拿名额做。

共享资源算账：测试库的连接上限要大于“进程数 × 每进程峰值连接”，两份全量同时跑会翻倍，这是排队的主要原因（实战项目实测：12 进程峰值 97 连接，上限 200）。

## 全量怎么跑得快

pytest 默认用 pytest-xdist 的 `-n <进程数> --dist loadfile`（进程数见个人配置）：按文件分组，同一个文件里的用例留在一个进程，抢固定锁或共享状态的用例不会被拆开；`--basetemp` 放到 `/tmp` 下。其他测试框架用各自按文件分片的办法。

提速先测量，再按瓶颈下手：
1. 先看加进程有没有用：进程数翻倍，墙钟几乎不变，说明瓶颈不在并发，而在单个用例的成本（实战项目11-09：8 进程 47 分半，12 进程 49 分半）。这时继续加进程只会撞连接上限。
2. 单个用例贵，常见原因是每个用例都重新建表、跑迁移、写种子。优先用数据库模板克隆（PostgreSQL 的 `CREATE DATABASE ... TEMPLATE`，按文件拷贝，比重建快得多），模板全局建一份、各进程共用；从模板来的库不再跑迁移。
3. 固定的 advisory 锁会让各进程的迁移排队；能按 schema 区分的键就带上 schema。
4. 拖尾：`--dist loadfile` 按文件分配，最慢的那个文件决定下限。用 junit 结果按文件算耗时，找出最慢的几个。只有抢固定锁或共享状态的文件才需要留在同一进程：给这些文件打 `xdist_group` 标记，改用 `--dist loadgroup`，其余用例逐个分配（`worksteal` 不认 `xdist_group`，pytest-xdist 3.8.0 源码核实）。改分配方式后要对比一次耗时和失败数。
5. 测试专用的数据库可以关持久化：`fsync`、`synchronous_commit`、`full_page_writes` 关掉，数据目录可放 tmpfs；只用于测试库。

跑完挂了，先把失败的文件单独串行复跑一遍，分清是并行引起的还是真有问题。墙钟类性能断言在并行下会抖，并行时不判、全量后单独串行跑一遍再判；这一遍也要在名额里跑，别被别的会话的负载污染。

单独跑能过、全量跑挂：先比对两次运行的临时目录（如 pytest basetemp）、工作目录、环境变量和目录权限，再怀疑测试之间互相污染（实战项目批13：WSL 工作区目录 775 引出 47 个假失败）。验收真数据库通过时看跳过数，不只看退出码（实战项目批13：连接串没传进去，PG 用例全部静默跳过，pytest 照样退出 0）。

## 界面验收和浏览器

- 界面验收按真实可用视口，不按整屏分辨率：2560×1440 屏幕用 viewport 2560×1300，1920×1080 屏幕用 1920×940（扣 Windows 任务栏和浏览器标签栏、地址栏），手机 390×844；主证据是视口截图，整页长图只作补充（2026-11-08 作者定）。写界面类任务说明时把这条抄进去。
- Playwright 在 WSL 无头运行，负责自动回归；ego-browser 负责 agent 手动验收、截图和登录态操作。默认使用 agent 专用配置（见 `模板/浏览器.md`，profile 见个人配置），不碰用户登录态；需要登录态的任务串行执行，不清理状态，提交、发送、删除前先问用户。
