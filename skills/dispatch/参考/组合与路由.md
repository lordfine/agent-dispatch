# 组合与路由

需要：底座层（magpie）。

## 组合：按额度换一整套模型

组合就是“每个角色组里放谁”的一份清单。在用的组合放在个人配置的 `组合/` 下（如 `~/.claude/派活配置/组合/Codex.txt`），`当前组合.txt` 记着现在用哪个；skill 自带的 `组合/` 下只有切换脚本和示例。示例有两份：`国产.txt` 是 Opus 主脑加国产模型干活，`Codex.txt` 是 Opus 主脑加 Codex 模型干活。各组合的分工、兜底顺序和推理档位写在文件里，以文件为准；用哪个组合见个人配置。

切换（会改 magpie 路由组，属于改 magpie，先跟用户说清楚再执行）：
```text
# Windows
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" Codex
# WSL（自动改用 Windows 的 magpie.exe，切的是同一个 magpie）
python3 ~/.claude/skills/dispatch/组合/切换组合.py Codex
```
脚本先在个人配置的 `组合/` 里找，找不到再用示例；逐行执行文件里的 magpie 命令，任何一行失败就停，成功后写 `当前组合.txt` 并打印 `magpie groups`。旧的 `切换组合.ps1` 只是转调它。切完派一个 explorer 小活，用 `magpie usage --csv --last 1h` 核对落点。

额度变化时调组合文件本身，不新建 agent：额度紧就把组里的强模型换成常规模型，或把 `:xhigh` 改 `:high`；额度松就反过来。改完重跑一次切换脚本。新增组合照着现有文件的格式写一份新的 txt。

`stays`（一段对话是否粘在上次答话的模型上）：国产组合是 auto；Codex 组合是 turn，每轮新对话重新从第一顺位选。原因：2026-11-05 夜里 chatgpt.com 经代理断连几次，auto 让对话一直粘在兜底模型上，约七成请求落到了兜底。切换前已经开始的对话可能还留在旧模型上，核对时看切换后新开的对话。

## 组名和档位

模型和组名都写 magpie 路由组名，不写供应商前缀；具体用到哪个模型只写在组合文件里。两类组：
- 角色组（agent 和 worker 用）：`explore`、`extract`、`research`、`review`、`diagnose`、`write`、`verify`、`impl-lite`、`impl`、`impl-strong`。
- 档位组：`glm-main`、`glm-fast`、`minimax`、`ds-flash`。Claude Code 的 fable/opus/sonnet/haiku/subagent 档位指向哪个组由组合文件末尾的 `magpie claude` 行决定，可能是档位组，也可能直接是角色组。

组名不带版本号，换来源或升级模型只改组成员并重新切换组合，agent、手册和 Orca 命令不用动。`magpie groups` 看每个组现在指向谁。

推理档位：组成员要么钉死档位（如 `codex/gpt-6.1-terra:medium:fast`），要么写成 `:medium+high+xhigh`。成员钉了档位，不管调用方要什么都按钉的发（magpie 源码 gateway.go 写明，11-09 诊断核实）；成员没钉档位时，收到 max 请求会被 magpie 跳过，整轮落到兜底模型上（2026-11-06 实测）。原生子代理的档位就靠成员上钉的。

## 每分钟请求上限

订阅类来源（如 Codex）的每分钟请求上限（数值见个人配置）按账号算、所有组共用，是真实的吞吐上限，worker 和工作流拉起的子代理抢同一份名额，开多了主要在排队。组里有非 Codex 兜底的（explore、extract、write），名额满时 magpie 会在发请求前直接让给兜底，落点里兜底占比高先查这个（11-09 诊断：explore 72 小时九成多落到 MiniMax 就是这个原因，不是档位不匹配）。

11-09 用 72 小时用量算过：单个活跃会话每分钟中位 1 次请求、九成不超过 4 次；7 个会话同时跑时合计中位约 9 次。平时并发上限和每分钟上限大致匹配，超限主要来自工作流一次拉起一批审查员的尖峰。

## 核对模型落点

```text
magpie usage --csv --last 1h   # 按 session × requested_model 核对落点
```
`脚本/落点检查.py` 可以挂在 Orca 定时任务上每小时跑一次，查到兜底偏高就弹 Windows 通知；`--precheck` 恒返回 1，不唤起 agent（设计如此）。`脚本/体检.py` 查 magpie、组合是否一致、Orca 和远程服务器、MCP、Orca 版本有没有变，以及个人配置里的扩展检查。

## magpie 智能路由（可选，没有主脑替你挑模型时用）

magpie 的 `routing=smart` 组可以按规则给每一轮挑模型：按意图（由一个判断模型分类）、推理档、消息长度、有没有图、项目文件夹、时间段，以及“压缩上下文”这类请求（`magpie group rule help`）。意图判断每轮只发一次请求（一条用户消息算一轮，worker 收到的一份规格就是一轮），判断模型最好用不占订阅名额的按量小模型。

有主脑时不推荐给 worker 用：主脑派活时手里有完整上下文，定组和档位比只看一条消息的分类器准，也更好追溯。适合的场景是同事只用 Codex 或 Sonnet 当主会话、没人替他挑模型的时候，可以用 `magpie group template smart` 建一个组当默认模型。
