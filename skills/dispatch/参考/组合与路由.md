# 组合与路由

需要：底座层（magpie）。

## 组合：按额度换一整套模型

组合就是“每个角色组里放谁”的一份清单。在用的组合放在个人配置的 `组合/` 下（如 `~/.dispatch/组合/Codex.txt`），`当前组合.txt` 记着现在用哪个；skill 自带的 `组合/` 下只有切换脚本和示例。示例有两份：`国产.txt` 是 Opus 主脑加国产模型干活，`Codex.txt` 是 Opus 主脑加 Codex 模型干活。各组合的分工、兜底顺序和推理档位写在文件里，以文件为准；用哪个组合见个人配置。

切换（会改 magpie 路由组，属于改 magpie，先跟用户说清楚再执行）：
```text
# Windows
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" Codex
# WSL（自动改用 Windows 的 magpie.exe，切的是同一个 magpie）
python3 ~/.claude/skills/dispatch/组合/切换组合.py Codex
```
脚本先在个人配置的 `组合/` 里找，找不到再用示例；逐行执行文件里的 magpie 命令，任何一行失败就停，成功后写 `当前组合.txt` 并打印 `magpie groups`。旧的 `切换组合.ps1` 只是转调它。切完派一个 explorer 小活，用 `magpie usage --csv --last 1h` 核对落点。

额度变化时调组合文件本身，不新建 agent：额度紧就把组里的强模型换成常规模型，或把 `:xhigh` 改 `:high`；额度松就反过来。改完重跑一次切换脚本。新增组合照着现有文件的格式写一份新的 txt。

`stays`（一段对话是否粘在上次答话的模型上）：国产组合是 auto；Codex 组合是 turn，每轮新对话重新从第一顺位选。原因：2026-11-05 夜里 chatgpt.com 经代理断连几次，auto 让对话一直粘在兜底模型上，约七成请求落到了兜底。切换前已经开始的对话可能还留在旧模型上，核对时看切换后新开的对话。

## 组名和档位

模型和组名都写 magpie 路由组名，不写供应商前缀；具体用到哪个模型只写在组合文件里。两类组：
- 角色组（agent 和 worker 用）：`explore`、`extract`、`research`、`review`、`diagnose`、`write`、`verify`、`impl-lite`、`impl`、`impl-strong`。
- 档位组：`glm-main`、`glm-fast`、`minimax`、`ds-flash`。Claude Code 的 fable/opus/sonnet/haiku/subagent 档位指向哪个组由组合文件末尾的 `magpie claude` 行决定，可能是档位组，也可能直接是角色组。

组名不带版本号，换来源或升级模型只改组成员并重新切换组合，agent、手册和 Orca 命令不用动。`magpie groups` 看每个组现在指向谁。

推理档位（依据 magpie 0.1.4940 源码，2026-11-28 实测）：一个请求最后按哪档发，从高到低是 成员上钉死的档位 → 组里带 `use-effort` 的规则 → 模型名后缀（`group/review:high` 这类）→ 调用方传的档位；都没有就不带，magpie 不补默认档。成员有两种写法：钉死一档（如 `codex/gpt-6.1-terra:medium`），或给一个范围（`:medium+high+xhigh`），范围内的由调用方选。调用方要的档位超出组的 `levels=` 或成员的范围时，改成范围里最近的一档，不报错；答题的模型自己没有这一档时，换成它有的最近一档。组上的 `levels=` 只管没写范围的成员，管不住自带范围的成员。GLM 和 DeepSeek 没有 medium 和 xhigh：medium 会发成 high，xhigh 会发成 max，所以国产兜底要钉死档位，别让它跟着调用方跑。

角色组因此分两种，示例 Codex 组合里都有；国产示例的角色都钉了档，调用方传什么都不起作用：
- 钉死的组（explore、extract、write、verify）：成员带单一档位，或者组里有一条无条件的 `use-effort` 规则。规则必须带条件，所以无条件规则写 `tokens=1`，它永远成立。调用方传什么都不起作用。便宜、派得勤的角色和必须最强的角色适合这样，保护额度。
- 由调用方定档的组（research、review、diagnose）：成员给范围，组上写 `levels=medium,high,xhigh`，不写无条件的档位规则，主脑按任务难度每次选档。需要保底时加一条带条件的规则，只在要拦的时候生效：`magpie group rule add review use=<第一顺位成员> use-effort=high when="effort <= medium"` 是“至少 high”，档位写 high、条件写 `when="effort >= xhigh"` 就是封顶在 high。规则在一轮开头匹配一次、整轮沿用，先写的先匹配；它同样作用到没钉档的兜底成员上。换掉旧规则先 `magpie group rule rm <组> <序号>`，`rule add` 不查重。`use=` 只在这个组自己的成员里找：写成员的模型名就行，不用抄档位范围和账号锁；成员是池组时写池组名。同一个模型在组里出现两次（两个档位或两个账号）时，要写成和成员一字不差。成员的写法改了（换范围、加减账号锁），规则就对不上，之后对这个组执行任何 `group set` 都会把那条规则删掉并提示，要重新加。

原生子代理实际发出去的档位（2026-11-16、11-28 两次实测）：
- 钉死的组：按钉的发，调用时传 `effort` 不起作用。
- 由调用方定档的组：Agent 工具调用时传 `effort` 生效，传 high 发 high、传 xhigh 发 xhigh，有保底规则的组传 medium 按保底的那档发；不传时带的是 Claude Code 的默认档（实测 medium），所以默认档写在角色文件里（`effort: high` 这类，11-29 实测生效），临时升降在调用时传。
- 走别名（`model="sonnet"`、`"fable"`）：按 `magpie claude <别名>_effort` 发，调用方传的也被覆盖。
- 工作流 `agent()` 把 `model` 写成带 levels 的组名（如 `group/impl`）并传 `effort`：照传。Agent 工具的 `model` 只认别名，做不到这一点。
- Orca worker 用 `--model group/<组> --effort <档>`；把档位写在模型名后面（`group/review:high`）也行，它优先于请求里的档位（按源码，没实测）。

`magpie claude <别名>_effort`、增删规则、改组成员都是改 magpie 配置，要用户同意。

重放组合前要知道：对同名组执行 `group add` 是整体替换，成员的“关闭”、组在界面里设的 sink、firstToken、patience、档位映射和组里原有的规则都会丢。组合文件里写了规则行的组，规则由后面的 `rule add` 行补回；没写的就没了，比如在界面里加的规则，或者靠规则钉档、文件里却没有这一行的组，重放后会变成由调用方定档。想在重放时保住这些，用 `group set` 改已有的组（手动执行，或把组合文件里那一行的 `add` 换成 `set`），它只动你写的字段；但它不删旧规则，`rule add` 又不查重，换规则要先 `magpie group rule rm <组> <序号>` 删掉旧的再加，否则每重放一次多一条。切换脚本只是逐行原样执行，不替你做这些判断。改路由组之前先留底：把 magpie 配置目录里的 `providers.json` 复制一份到外面（路由组、规则、成员关闭都在这一个文件里，含供应商密钥，只能留在本机），会动设置的再复制 `settings.json`，并记下反向命令。回滚优先反向执行命令；整份拷回去不用重启（按源码），要先写成临时文件再改名覆盖，拷完发一条最小请求、看 trace 确认网关用的是新文件。`magpie save` 的快照不含路由组和规则，撤不回改组；magpie 自己留的 `.bak` 只有一代、可能是中间状态，`auto-backups` 是整套设置的日备份、恢复也是整套，都不能当改前备份。

组行里认的键和 magpie 一致（依据 0.1.4940 源码）：`group add` 和 `group set` 认的键一样，键名不分大小写，别名也认（`members`、`model` 是 `models`，`strategy` 是 `routing`，`use` 是 `pick` 等），别名和正名当成同一个键，同一行写两个会报重复。`fast=`、`ultra=`、`weight=`、`pick=` 指向成员：`group add` 里四个都要写在 `models=` 后面，成员要先由 `models=` 加进组；`models=` 还会清空 fast 和 ultra，所以 `group set` 里这两个也要写在它后面。写反了解析器会拦下并说明原因。`models+=`、`models-=`（`members`、`model` 同理）是在现有成员上追加或移除，别用：体检没法据此核对组合，写完整的 `models=`。

`magpie claude opus`、`sonnet`、`haiku`、`fable` 后面不带值是写操作：把 Claude Code 主模型换成 Claude 自带模型，同时让它绕开 magpie，所有会话会断；`magpie claude default` 直接把 magpie 摘掉。查看只用不带参数的 `magpie claude`，改别名一律写明值，参数不用变量（实战项目批14 复盘：主会话把这几条当查询循环跑，所有会话断了约一分钟）。可以在 `~/.claude/settings.json` 的 PreToolUse 挂一个钩子，在 Bash、PowerShell 里拦下这几种写法。

兜底黏住还有一种来源：第一顺位被内容过滤（如 Codex 的 cyber_policy）拒绝后，order 路由退到第二顺位，stays=turn 让这个子代理余下的请求都留在兜底上（实战项目批14：一次拒绝之后，凌晨审查组的请求大半落到更贵的兜底模型）。兜底不要放比第一顺位更贵的模型，除非是专门的复核组。

## 每分钟请求上限

订阅类来源（如 Codex）的每分钟请求上限（数值见个人配置）按账号算、所有组共用，是真实的吞吐上限，worker 和工作流拉起的子代理抢同一份名额，开多了主要在排队。名额满了不会直接报 429，超出的请求先排队（最多等约 120 秒）。组里有非 Codex 兜底的（explore、extract、write；review、diagnose、impl 这类第一顺位是 Codex、后面还有国产成员的组也算），名额满时 magpie 会改选组里能马上发的兜底成员，那一刻第一顺位根本不被尝试，也不报错，发出去的是兜底钉的档位；组设了 `stays=turn` 时，这一轮对话剩下的请求都留在兜底上。所以兜底占比高，大部分是一次改选后整轮黏住，不等于每条请求都撞了限额（11-09、11-16 两次诊断：explore 九成多落到 MiniMax 就是这个原因，不是档位不匹配；2026-11-29 又见到一次，别的会话开着 4 个 Codex worker，名额一直是满的，一次审查的 49 条请求整轮落在兜底上，要的是 xhigh、发的是兜底钉的 high）。要它们必须走 Codex，就把外部兜底从组里去掉，代价是名额满时排队（2026-11-29 读 trace：Codex 忙的时候，只有 Codex 一个成员的组每条请求排队中位约 16 秒、最长约 19 秒），而且 Codex 自己出错时请求直接报错，没有兜底接着。

11-09 用 72 小时用量算过：单个活跃会话每分钟中位 1 次请求、九成不超过 4 次；7 个会话同时跑时合计中位约 9 次。平时并发上限和每分钟上限大致匹配，超限主要来自工作流一次拉起一批审查员的尖峰。

## 核对模型落点

```text
magpie usage --csv --last 1h   # 按 session × requested_model 核对落点
```
看用量统计时注意三点（2026-11-16 复盘）：`source=log` 的行是 magpie 从别的客户端日志导入的（比如用户自己的 Codex 客户端），不是派活产生的，统计时去掉；导入行的状态记成 0，不代表失败；`time` 列是请求进 magpie 的时间，排队等名额的请求实际发出要晚一些，按时间对 worker 时留点余量。

测档位时看 magpie 的 trace：对本机 magpie 网关发 `GET /v1/magpie/trace`（地址就是 Claude Code 配置里连的那个网关），它同时记要的档位和每次尝试实际发给谁、发了哪档，只留最近 60 条，发完请求马上看。`magpie usage` 的 effort 列只有实际发出的档位，看不到要的档位。

`脚本/落点检查.py` 可以挂在 Orca 定时任务上每小时跑一次，查到兜底偏高就弹 Windows 通知；`--precheck` 恒返回 1，不唤起 agent（设计如此）。`脚本/体检.py` 查 magpie、组合是否一致、Orca 和远程服务器、MCP、Orca 版本有没有变，以及个人配置里的扩展检查。

## magpie 智能路由（可选，没有主脑替你挑模型时用）

magpie 的 `routing=smart` 组可以按规则给每一轮挑模型：按意图（由一个判断模型分类）、推理档、消息长度、有没有图、项目文件夹、时间段，以及“压缩上下文”这类请求（`magpie group rule help`）。意图判断每轮只发一次请求（一条用户消息算一轮，worker 收到的一份规格就是一轮），判断模型最好用不占订阅名额的按量小模型。

有主脑时不推荐给 worker 用：主脑派活时手里有完整上下文，定组和档位比只看一条消息的分类器准，也更好追溯。适合的场景是同事只用 Codex 或 Sonnet 当主会话、没人替他挑模型的时候，可以用 `magpie group template smart` 建一个组当默认模型。
