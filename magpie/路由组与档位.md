# magpie 路由组与档位配置

这套配置里所有模型都写成 magpie 路由组名（`group/<id>`），不写供应商前缀。组名不带版本号，以后换来源或升级模型，只改组成员，agent 文件、派活手册、Orca 命令都不用动。

组分成两类，别混：

- 角色组按"干什么"命名，agent 文件和 worker 用。示例里一共十个：`explore`、`research`、`extract`、`review`、`diagnose`、`write`、`verify`、`impl-lite`、`impl`、`impl-strong`。
- 档位组给 Claude Code 的别名档位用。示例里一共四个：`glm-main`、`glm-fast`、`minimax`、`ds-flash`。别名档位（fable、opus、sonnet、haiku、subagent）也可以直接指向角色组或具体模型，示例 Codex 组合就是这样，见第 2 节。

角色组里放谁由"组合"决定，见第 3 节。下面命令里的 `<国产来源>`、`<Codex来源>`、`<Claude来源>` 换成你在 magpie 里的供应商 id（`magpie providers` 可以看到），一个组合里可能用到不止一个来源。

## 1. 先留底

改路由组之前，把 magpie 配置目录里的 `providers.json` 复制一份到外面：路由组、规则、成员关闭都在这一个文件里（它含供应商密钥，只能留在本机）。会动设置的再复制 `settings.json`，并记下反向命令。

回滚优先反向执行命令，只动改过的组。整份拷回去不用重启（按源码），要先写成临时文件再改名覆盖，拷完发一条最小请求、看 trace 确认网关用的是新文件。

`magpie save` 的快照存的是各客户端的设置，不含路由组和规则，撤不回改组；magpie 自己留的 `.bak` 只有一代、可能是中间状态，`auto-backups` 是整套设置的日备份、恢复也是整套，都不能当改前备份。

## 2. 建四个档位组

档位组给没有写死角色组的地方用：`general-purpose`、手动开的实现会话、技能里不指定类型的子代理。

```text
magpie group add glm-main models=<国产来源>/glm-5.3:high routing=order levels=medium,high,xhigh
magpie group add glm-fast models=<国产来源>/glm-5.3-flash:high routing=order levels=medium,high,xhigh
magpie group add minimax  models=<国产来源>/MiniMax-M3.1-Flash:medium+high+xhigh routing=order levels=medium,high,xhigh
magpie group add ds-flash models=<国产来源>/deepseek-flash:high routing=order levels=medium,high,xhigh
```

`magpie groups` 确认四个组都在。

然后让 Claude Code 的档位指向组。别名档位按大小排：fable 最大，给复杂票、非标准任务；opus 其次，给普通实现；sonnet 再次，给确定性的清单活；haiku 最小，Claude Code 自己生成标题、摘要等后台小活也走它，别指向订阅类来源，否则会挤占每分钟请求名额。subagent 是没写 model 的子代理的默认落点。

国产示例：

```text
magpie claude fable    group/glm-main
magpie claude opus     group/glm-main
magpie claude sonnet   group/glm-fast
magpie claude subagent group/glm-fast
magpie claude haiku    <国产来源>/MiniMax-M3.1-Flash
```

Codex 示例的别名不指向档位组：fable 指向实现角色组 `group/impl-strong`，opus、sonnet、haiku 直接指向国产模型，subagent 不设（没写 model 的子代理跟随主会话，派活一律用具名角色）。示例没有给别名钉推理档。具体指向以 `组合/Codex.txt` 末尾为准。

这些行写在组合文件末尾，切组合时一起生效。

每条命令都必须带模型值。`magpie claude opus` 这种不带值的写法会把 magpie 从该档位摘掉。

opus 档指向 glm-main 是有意的：Opus 主会话里 `model="opus"` 会解析成主会话自己，所以 opus 档实际只在非 Opus 会话里生效。真正要用 Opus 的地方（示例国产组合里的 verifier、主会话）走角色组 `verify` 或直接写 `<Claude来源>/claude-opus-5-5`。

具体的档位指向以在用组合文件末尾的 `magpie claude` 行为准，`magpie claude` 能看到现在指向哪里。

## 3. 用组合文件建角色组

示例里的十个角色组不用手敲，它们由组合文件决定。skill 里的 `组合/` 放两份示例，初始化引导会复制一份到个人配置 `~/.dispatch/组合/` 下，把来源换成你的：

- `国产.txt`：以 GLM / MiniMax / DeepSeek 为成员的参考示例。
- `Codex.txt`：以 Codex 模型为主的参考示例，探索、抽取兜底是 MiniMax，写文档兜底是 DeepSeek，其余组用另一个 Codex 模型兜底。

切换组合就是逐行执行组合文件里的 magpie 命令：

```text
# Windows
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" Codex
# WSL（自动改用 Windows 的 magpie.exe，切的是同一个 magpie）
python3 ~/.claude/skills/dispatch/组合/切换组合.py Codex
```

脚本先在个人配置的 `组合/` 里找组合文件，找不到再用示例；任何一行失败就停，成功后在个人配置里写 `当前组合.txt`，再打印 `magpie groups`。旧的 `切换组合.ps1` 只是转调 `切换组合.py`。

重放前要知道：对同名组执行 `group add` 是整体替换，成员的“关闭”、组在界面里设的东西和组里原有的规则都会丢；组合文件里写了规则行的组，规则由后面的 `rule add` 行补回，没写的就没了。想在重放时保住这些，改用手动的 `group set`，它只动你写的字段；但它不删旧规则，`rule add` 又不查重，换规则要先删掉旧的再加。留底办法见第 1 节。

组行里认哪些键（依据 magpie 0.1.4940 源码）：`group add` 和 `group set` 认的键一样，键名不分大小写，多数键还有别名，比如 `models`（`members`、`model`）、`routing`（`strategy`）、`stays`（`stay`、`affinity`）、`levels`（`level`）、`note`（`description`、`desc`、`remark`）、`effort`（`reasoning`）、`weight`（`weights`）、`pick`（`use`）。`fast=`、`ultra=`、`weight=`、`pick=` 指向成员，要等成员进了组才认得：`models=` 换的是整份名单，还会把 fast 和 ultra 清空，所以 `fast=`、`ultra=` 要写在 `models=` 后面（add、set 都是），否则先写的会被悄悄清掉；`group add` 里四个都要写在 `models=` 后面，所指的成员不在组里时整条命令失败、什么都不保存。`pick=` 会把路由方式改成 manual，后面再写 `routing=` 会盖回去。追加、移除成员是另外六个键：`models+=`（别名 `members+=`、`model+=`）和 `models-=`（别名 `members-=`、`model-=`），组合文件里别用，写完整的 `models=`：体检没法据此核对组合是否一致。`group set` 里的 `id=` 是给组改名，别写进每次重放都会执行的行。

要加一个新组合，照现有文件的格式写一份新的 txt，每行一条 magpie 命令，`#` 开头是注释。选成员时按任务特点来：探索和抽取偏重速度与成本，审查和复核偏重能力，实现按难度分开；没有唯一正确的搭配。

## 4. 推理档位只用 medium、high、xhigh

示例配置把档位收在 `medium`、`high`、`xhigh` 三档，分别用于简单、常规和困难任务；读者可根据模型支持、质量要求和费用调整，不必照搬。

成员写法是 `供应商/模型[:推理档位][:fast]`。一个成员可以写多档，表示"这几档都接，具体用哪档由调用方决定"：

```text
models=<Codex来源>/gpt-6.1-sol:medium+high+xhigh:fast
```

组上还要写 `levels=medium,high,xhigh`，把这一组的可选档位收在这三档里：

```text
magpie group add impl models=<Codex来源>/gpt-6.1-sol:medium+high+xhigh:fast,<国产来源>/glm-5.3-flash:high routing=order stays=turn levels=medium,high,xhigh
```

各家的差别要记住：

- GLM 和 DeepSeek 自己只有 low / high / max，没有 medium 和 xhigh。所以组里落到它们身上时一律钉 `:high`。
- MiniMax 有 low / medium / high / xhigh / max，写成 `:medium+high+xhigh`，不低于 medium。
- Codex 成员同样写成 `:medium+high+xhigh`，由 `--effort` 在三档里选。

传了范围外的档位，magpie 会换成最接近的那一档。在一台测试机上，2026-11-06 给 impl-strong 传 max，落到 astra 时是 xhigh。

调用方要的档位超出成员的范围或组的 `levels=` 时，magpie 会改成最近的一档，不报错（依据 0.1.4940 源码）。所以把成员的 `:medium+high+xhigh` 和组上的 `levels=` 写全，档位就收在三档里；范围写窄了，高档请求会被悄悄降下来，要核对落点才看得出来。

角色组因此分两种，示例 Codex 组合里都有：

- 钉死的组（explore、extract、write、verify）：成员带单一档位，或者组里有一条无条件的规则（条件写 `tokens=1`，它永远成立）。调用方传什么都不起作用。
- 由调用方定档的组（research、review、diagnose）：成员写 `:medium+high+xhigh`，组上写 `levels=medium,high,xhigh`，不写无条件的档位规则，主脑派活时按任务难度传档。要保底就加一条带条件的规则，例如 `magpie group rule add review use=<Codex来源>/gpt-6.1-sol use-effort=high when="effort <= medium"` 是“至少 high”。规则里 `use=` 写组里成员的模型名（成员是别的组时写那个组名），不用抄档位范围和账号锁；同一个模型在组里出现两次时要写成和成员一字不差；成员的写法改了，规则要重新加。国产示例的角色都钉了档，因为 GLM、DeepSeek 没有 medium 和 xhigh，放开的话 xhigh 会发成 max。

## 5. stays：一段对话粘不粘在上次的模型上

`stays` 控制一段对话是否继续用上次答话的模型：

- `auto`：粘住上次的模型，直到它不可用。示例的国产组合用这个。
- `turn`：每轮新对话都从第一顺位重新选。示例的 Codex 组合用这个。

示例的 Codex 组合用 `turn`，依据是一次测试环境里的实测：2026-11-05 夜里 chatgpt.com 经代理断连了几次，`auto` 让对话一直粘在兜底的 GLM 上，约七成请求落到了 GLM，主模型反而闲着。`turn` 让每轮都先试主模型，试不上才顺延。其他组合按自己的路由需要选择。

切换组合前已经开始的对话，可能还留在旧模型上。核对落点时看切换之后新开的对话，别拿旧会话下结论。

## 6. 升级模型

角色组改组合文件，改完重跑一次切换脚本。比如 GLM 出了 5.5：

```text
# 把 国产.txt 里的 glm-5.3 改成 glm-5.5，然后
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" 国产
```

档位组直接改成员：

```text
magpie group set glm-main models=<国产来源>/glm-5.5
```

## 7. 核对落点

```text
magpie usage --csv --last 1h
```

看 `requested_model`、`served_model`、`effort` 三列，确认每个 agent 和 worker 落在预期的模型和推理档位上。`requested_model` 是角色组名，`served_model` 是实际落到的模型；对不上就 `magpie groups` 看组里现在是谁。

测档位时看 magpie 的 trace：对本机 magpie 网关发 `GET /v1/magpie/trace`（地址就是 Claude Code 配置里连的那个网关），它同时记要的档位和每次尝试实际发给谁、发了哪档，只留最近 60 条，发完请求马上看。`magpie usage` 的 effort 列只有实际发出的档位，看不到要的档位。
