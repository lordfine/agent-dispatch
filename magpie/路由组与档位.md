# magpie 路由组与档位配置

这套配置里所有模型都写成 magpie 路由组名（`group/<id>`），不写供应商前缀。组名不带版本号，以后换来源或升级模型，只改组成员，agent 文件、派活手册、Orca 命令都不用动。

组分成两类，别混：

- 角色组按"干什么"命名，agent 文件和 worker 用。示例里一共九个：`explore`、`research`、`extract`、`review`、`diagnose`、`write`、`verify`、`impl`、`impl-strong`。
- 档位组按 Claude Code 的别名档位命名，`~/.claude/settings.json` 里的 opus、sonnet、haiku、fable 指向它们。示例里一共四个：`glm-main`、`glm-fast`、`minimax`、`ds-flash`。

角色组里放谁由"组合"决定，见第 3 节。下面命令里的 `<国产来源>`、`<Codex来源>`、`<Claude来源>` 换成你在 magpie 里的供应商 id（`magpie providers` 可以看到），一个组合里可能用到不止一个来源。

## 1. 先存一份快照

```text
magpie save 改前-路由组
```

想撤回时 `magpie use 改前-路由组`。

## 2. 建四个档位组

档位组给没有写死角色组的地方用：`general-purpose`、手动开的实现会话、技能里不指定类型的子代理。

```text
magpie group add glm-main models=<国产来源>/glm-5.3:high routing=order levels=medium,high,xhigh
magpie group add glm-fast models=<国产来源>/glm-5.3-flash:high routing=order levels=medium,high,xhigh
magpie group add minimax  models=<国产来源>/MiniMax-M3.1-Flash:medium+high+xhigh routing=order levels=medium,high,xhigh
magpie group add ds-flash models=<国产来源>/deepseek-flash:high routing=order levels=medium,high,xhigh
```

`magpie groups` 确认四个组都在。

然后让 Claude Code 的档位指向组：

```text
magpie claude opus   group/glm-main
magpie claude sonnet group/glm-main
magpie claude haiku  group/minimax
magpie claude fable  group/glm-fast
magpie claude subagent group/glm-fast
magpie claude haiku_effort medium
magpie claude subagent_effort high
```

每条命令都必须带模型值。`magpie claude opus` 这种不带值的写法会把 magpie 从该档位摘掉。

opus 档指向 glm-main 是有意的：Opus 主会话里 `model="opus"` 会解析成主会话自己，所以 opus 档实际只在非 Opus 会话里生效。真正要用 Opus 的地方（示例国产组合里的 verifier、主会话）走角色组 `verify` 或直接写 `<Claude来源>/claude-opus-5-5`。

具体的档位指向以你机器上的 `settings.json` 为准，上面是一份能用的示例。

## 3. 用组合文件建角色组

示例里的九个角色组不用手敲，它们由 `~/.claude/skills/dispatch/组合/` 下的组合文件决定：

- `国产.txt`：以 GLM / MiniMax / DeepSeek 为成员的参考示例。
- `Codex.txt`：以 Codex 模型为首选、国产模型为兜底的参考示例。

切换组合就是逐行执行组合文件里的 `magpie group add`：

```text
# Windows
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" Codex
# WSL（自动改用 Windows 的 magpie.exe，切的是同一个 magpie）
python3 ~/.claude/skills/dispatch/组合/切换组合.py Codex
```

脚本任何一行失败就停，成功后写一份 `当前组合.txt` 记录当前用的是哪个组合，再打印 `magpie groups`。`当前组合.txt` 是本机生成的，不进仓库。旧的 `切换组合.ps1` 只是转调 `切换组合.py`。

要加一个新组合，照现有文件的格式写一份新的 txt，每行一条 `magpie group add`，`#` 开头是注释。选成员时按任务特点来：探索和抽取偏重速度与成本，审查和复核偏重能力，实现按难度分开；没有唯一正确的搭配。

## 4. 推理档位只用 medium、high、xhigh

示例配置把档位收在 `medium`、`high`、`xhigh` 三档，分别用于简单、常规和困难任务；读者可根据模型支持、质量要求和费用调整，不必照搬。

成员写法是 `供应商/模型[:推理档位][:fast]`。一个成员可以写多档，表示"这几档都接，具体用哪档由调用方决定"：

```text
models=<Codex来源>/gpt-6.1-sol:medium+high+xhigh:fast
```

组上还要写 `levels=medium,high,xhigh`，把这一组的可选档位收在这三档里：

```text
magpie group add impl models=<Codex来源>/gpt-6.1-sol:medium+high+xhigh:fast,<国产来源>/glm-5.3-flash:high routing=order stays=turn levels=medium,high,xhigh
```

各家的差别要记住：

- GLM 和 DeepSeek 自己只有 low / high / max，没有 medium 和 xhigh。所以组里落到它们身上时一律钉 `:high`。
- MiniMax 有 low / medium / high / xhigh / max，写成 `:medium+high+xhigh`，不低于 medium。
- Codex 成员同样写成 `:medium+high+xhigh`，由 `--effort` 在三档里选。

传了范围外的档位，magpie 会换成最接近的那一档。在一台测试机上，2026-11-06 给 impl-strong 传 max，落到 astra 时是 xhigh。

这里有个改之前的坑：Codex 成员如果没写档位，收到 max 请求会被 magpie 跳过，整轮落到兜底的 GLM 上。看起来是"请求成功了"，其实干活的换成了便宜模型。所以 Codex 成员必须把 `:medium+high+xhigh` 和组上的 `levels=` 都写全。

## 5. stays：一段对话粘不粘在上次的模型上

`stays` 控制一段对话是否继续用上次答话的模型：

- `auto`：粘住上次的模型，直到它不可用。示例的国产组合用这个。
- `turn`：每轮新对话都从第一顺位重新选。示例的 Codex 组合用这个。

示例的 Codex 组合用 `turn`，依据是一次测试环境里的实测：2026-11-05 夜里 chatgpt.com 经代理断连了几次，`auto` 让对话一直粘在兜底的 GLM 上，约七成请求落到了 GLM，主模型反而闲着。`turn` 让每轮都先试主模型，试不上才顺延。其他组合按自己的路由需要选择。

切换组合前已经开始的对话，可能还留在旧模型上。核对落点时看切换之后新开的对话，别拿旧会话下结论。

## 6. 升级模型

角色组改组合文件，改完重跑一次切换脚本。比如 GLM 出了 5.5：

```text
# 把 国产.txt 里的 glm-5.3 改成 glm-5.5，然后
python "$HOME\.claude\skills\dispatch\组合\切换组合.py" 国产
```

档位组直接改成员：

```text
magpie group set glm-main models=<国产来源>/glm-5.5
```

## 7. 核对落点

```text
magpie usage --csv --last 1h
```

看 `requested_model`、`served_model`、`effort` 三列，确认每个 agent 和 worker 落在预期的模型和推理档位上。`requested_model` 是角色组名，`served_model` 是实际落到的模型；对不上就 `magpie groups` 看组里现在是谁。
